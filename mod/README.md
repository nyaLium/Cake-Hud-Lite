## 绘制方式（1.15.0 起）

血条**画在世界空间**，与实体名字共用原版那条提交路径：

- 文字行 → SubmitNodeCollector.submitNameTag（原版画名字的同一个函数，DisplayMode.NORMAL）；
- 血条 → submitCustomGeometry + RenderTypes.text(boss_bar PNG)，同样的 billboard 变换。

结果是遮挡行为**与原版名字一致**：被方块挡住就消失、被更近的模型逐像素裁掉、
尺寸随距离缩放。1.0.0 起不再按方块/实体遮挡剔除（`shouldRender` 之外只按距离判断）。

## 显示效果

```
        ❤120/120 💛40 | 🛡3 🔥5    ← 放得下：一行（红心写「当前/上限」，同类只用空格隔开）
        ▬▬▬▬▬▬ 原版 bossbar 纹理 ▬▬▬▬▬▬
        冰霜狼                      ← 原版名称（本 Mod 只摘掉下面那行分数）

        ❤200/200                    ← 放不下：红心单独占上面一行
        💗5 | 🛡5 🔥3 ☃1            ← 其余心 + 护甲留在下面一行（换行代替了那个 |）
        ▬▬▬▬▬▬ 原版 bossbar 纹理 ▬▬▬▬▬▬
        冰霜狼
```

| 行 | 距离锚点 | 说明 |
| --- | --- | --- |
| 心数 / 护甲 | -18 ~ -9 像素（折行时上面的行到 -27 起） | 固定，无垂直微调（1.0.0 起删掉） |
| 血条 | -7 ~ -2 像素 | 原版 bossbar 纹理，5 像素高 |
| 名称（原版） | 0 ~ 9 像素 | 分数一摘，原版自己就落回这一行 |

坐标单位是「原版名牌像素」，1 像素 = 0.025 格，锚点复用原版名牌锚点
（`EntityAttachment.NAME_TAG` + 0.5 格），所以与原生名牌同字号、同远近缩放。

> 名字为什么自己就下来了：`EntityRenderer.submitNameDisplay` 的那次上抬
> `9 × 1.15 × 0.025` 写在 `if (scoreText != null)` 里。本 Mod 把 `below_name` 分数摘掉后，
> 上抬不再执行，名字自然落回 `y ∈ [0, 9]`（原来分数占的那行），所以不需要自己画名字。

血条用**原版 bossbar 纹理**（`red / yellow / purple / blue` 四套），按当前显示的心类换色：

| 心类 | 血条 | 图标 | 数据包通道 |
| --- | --- | --- | --- |
| 红心 | 红 | ❤ 当前/上限 | `HeartValue=1`（敌方条颜色 `blue`） |
| 魂心 | **黄** | 💛 | `HeartValue=2`（敌方条颜色 `yellow`） |
| 黑心 | **紫** | 🖤 | `HeartValue=3`（玩家条颜色 `purple`） |
| 蓝心 | **蓝** | 💙 | `HeartValue=4`（玩家条颜色 `blue`） |
| 碎心 | — | 💔 暗红 | `CrackedHearts > 0`，客户端拿不到（只在服务端组件里推） |
| 粉心 | — | 💗 亮紫 | `CrackedHearts < 0`（取绝对值），同样是 `CrackedHearts` 这一栏 |

## 心数怎么算出来的（纯客户端）

数据包 `misc/health.mcfunction`：

```
AllHearts = RedHearts + SoulHearts + BlackHearts + BlueHearts
RedHearts = min(RedHearts, MaxHP)          # MaxHP = 红心上限
伤害顺序：蓝 → 黑 → 魂 → 红                 # 前面全空，红心才掉
```

所以 **红心恒等于 `min(AllHearts, MaxHP)`**，多出来的部分只能是其余心。
敌人只可能带魂心（带 `NoSoulHearts` 标签的怪连魂心都没有），于是：

```
红心 = min(AllHearts, MaxHP)
魂心 = AllHearts - 红心
```

两个数都在客户端 Boss 栏标题里（`名字 (HP 120/100) 🛡3`），
所以**敌人心数 100% 精确，不需要任何服务端组件**。

## 数据来源（客户端必装 / 服务端选装）

| 数据源 | 能拿到什么 | 覆盖 | 需要服务端吗 |
| --- | --- | --- | --- |
| **服务端组件 `ctt-hud-fork:mob_health`** | 按 **UUID** 的 `AllHearts / MaxHP / 护甲 / 红魂黑蓝碎` | 视野内最近 32 只怪 | 选装 |
| 客户端 Boss 栏 `targetting*` 标题 | 精确 `AllHearts / MaxHP` + `🛡防御` + 元素护甲 | 被地图锁定的那一只 | 否 |
| 同一条 bar 的 progress / color | 当前心类的剩余比例 + 是哪一类心 | 同上 | 否 |
| `below_name` 展示槽的 `HealthPercent` | 0~100 百分比（红心口径） | 视野内全部敌人 | 否 |
| 队伍条 `spectator_bossbar` | 每名队友的 `AllHearts / MaxHP` | 队伍条存在时 | 否 |

敌人判据是「有没有 CTT 的血量分数」，**不用 scoreboard tag**（原版不同步实体标签，客户端永远是空集）。

### 三种安装组合

| 客户端 | 服务端 | 效果 |
| --- | --- | --- |
| ✅ | ❌ | 被锁定的那只 `x/y` + 心数；其余怪只有百分比 |
| ✅ | ✅ | **每只怪**都有 `x/y` + 护甲 + 各类心，同名怪也不串（按 UUID） |
| ❌ | ✅ | 服务端什么都不发（`canSend` 为假），零副作用 |

单机（集成服务器）自动等于「两端都装」。

### 服务端组件协议

`MobHealthPayload`（S2C，每 4 tick = 5 Hz，差量 + 3 s keepalive）：

| 字段 | 说明 |
| --- | --- |
| `version` | 协议版本，客户端遇到更高版本整包忽略 |
| `entries[]` | 最近 32 只怪，按距离 |

单条：`uuid / hp(AllHearts) / maxHp / soul / black / blue / cracked / maxSoul / maxBlack / maxBlue / defence / armour[7] / targetted`。
可负字段用 zigzag varint，一只怪约 40 字节。红心由 `AllHearts - 魂 - 黑 - 蓝` 反算。
客户端在 5 s 内收到包才用，超时自动回落到纯客户端路径（`ClientMobHealthCache`）。

### 上方 Boss 栏的两条如何识别

| Boss 条 | 形状 | 识别方式 |
| --- | --- | --- |
| 最近敌人信息（`targetting*`） | `名字 (HP 120/100) 🛡3` | 括号里有 `HP` 前缀 |
| 队伍血量（`spectator_bossbar`） | `A (10/20) B (30/40) (/) …` | 至少一段名字能匹配到**玩家列表**里的真实玩家 |
| 高塔层数（`floor`） | `高塔 (12/50)` | 名字是场景名，匹配不到玩家 → **不会被误隐藏** |

队伍条标题按 10 个槽位拼，空槽会渲染成 ` (/) ` 残渣，所以判定走两道：
先严格整串解析（`TeamBarTitle.parse`），失败再宽松扫描（`TeamBarTitle.scanLoose`）。
名字匹配来源有本地玩家、视野内玩家实体、以及 Tab 名单（`getPlayerInfo`）三路 ——
最后一路很关键，队伍条会列出不在渲染距离内的队友。

### 队友的心数

玩家独有的黑心 / 蓝心只出现在**玩家自己**的 `player_1001..1010` 上，而那条 bar
用 `bossbar set ... players @a[scores={BossbarID=100N}]` 只发给本人；
队友能看到的 `spectator_bossbar` 标题里只有 `AllHearts/MaxHP` —— **纯客户端拆不开四色心**。

所以：

| 服务端组件 | 队友那一行 |
| --- | --- |
| 没装 | `当前/最大`（不做近似，宁缺毋假） |
| 装了（1.16.0 起） | 和敌人一样的心数行：`❤60/150` + `💛40 🖤30 💙20 💔2`，碎心/粉心也在 |

服务端会把**附近的其他玩家**也按 UUID 推进 `mob_health`（字段与怪完全一样），
客户端 `resolveData` 优先用它，拿不到才回退队伍条。

## 同名敌人的唯一认领

装了服务端组件时**根本不需要认领**：数据按实体 UUID 走，名字再像也不会串。

纯客户端时没有 UUID，只能靠两个信号把那条 Boss 栏锁到唯一一只：

1. **`below_name` 的 `HealthPercent`**：只有真正被锁定的那只，它的百分比才等于
   bar 里的 `min(AllHearts, MaxHP) * 100 / MaxHP`（整数截断，与 `misc/health.mcfunction:102-104` 同口径）；
2. **绑定粘性**：按 bar 的 UUID 记住上一帧绑到哪只实体，只要它还在候选里就优先继续绑
   —— 名字一样的两只怪贴得很近时，数字不会在它们之间来回跳。

打分顺序（从强到弱）：百分比精确吻合 → 差 ≤ 2（同步差一两个 tick）→ 名字完全相同 →
上一帧绑定 → 最后才是距离。都匹配不上时宁可不给绝对值（那只怪退回百分比条），
也不会把数字挂到错的怪头上。

| 设置项 | 取值 | 说明 |
| --- | --- | --- |
| 显示盾牌指示器 | 开 / 关 | 总开关关闭时整栏灰掉 |
| 缩放比例 | **0.50 ~ 1.50**（步长 **0.05**，默认 **0.70**，不再带「倍」） | 整张纹理等比缩放到 `34k × 86k`，**不是平铺** |

**1.20.40 起位置是相对的**：`shieldX/Y` 与面板的 `selfStatsX/Y` 一样，都是「在 `layoutGuiW × layoutGuiH`
这套 GUI 下量的像素」，绘制时按 `当前尺寸 ÷ 记录尺寸` 换算
（`HudConfig.scalePos` / `shieldPosition` / `panel(..., guiW, guiH)`）。窗口放大一倍，指示器也到两倍远处；
靠边的因 `clampInto` 贴边（夹取只影响绘制，不改存储值）。拖动时 `setShieldPosition(..., guiW, guiH)`
会先把坐标换算到新参考系并记下新尺寸，所以不会越拖越偏。

> 1.20.22 修的核心：之前用 10 参数 `blit(pipeline, tex, x, y, u, v, w, h, texW, texH, color)`，
> 它的 `w/h` **同时是源区尺寸**，放大到 k 倍时 UV 跨了 k 张纹理 → 画成 k×k 平铺
> （1.2 倍能看见右下多两条）。现在改用 13 参数重载，显式给「目标宽高 + 源区宽高 + 纹理宽高」。

## 自动开队伍条（3 s 冷却 / 5 次失败 → 10 分钟熔断）

## 聊天栏不再被自己的命令刷屏

`ChatTriggerFilter`（注册在 `ClientReceiveMessageEvents.ALLOW_GAME`），只在自己刚发过命令的 3 秒内过滤，
手动敲 `/trigger` 不受影响：

| 吞掉的消息 | 判定 |
| --- | --- |
| 成功回显 | 文本含 `Triggered` / `已触发` 且含 `TogglePartyBossbar` |
| 失败报错 | 翻译键以 `commands.trigger.failed` 开头（「无法触发该计分项」） |

`ViewStats` 那几十行属性走的是另一条路（`SelfStats.onGameMessage`）：**只有我们自己触发的那趟**才吞，
玩家手动敲 `/trigger ViewStats` 照常显示（1.20.24）。

1.20.39 起补上「进存档那一刻」：世界载入时（玩家卡在「加载地形」）问 ViewStats，服务端要隔好几秒才回，
而一趟采集 3 s 就超时收尾了，迟到的这批会被误判成「玩家手动触发」、整批刷进聊天栏。
现在 `ClientPlayConnectionEvents.JOIN` 一到就记一笔（`SelfStats.onWorldJoined`），**3 s 内不发 trigger**、
这期间来的 ViewStats 输出也直接丢掉（`JOIN_GRACE_MS`）；
等世界跑起来再问，一问一答都是毫秒级，问题自然没有。详见
[属性面板](#自身属性面板1203纯客户端) 那节的「防刷屏」。

> 1.20.38 试过另一条路（把「迟到的输出」按 20 s 窗口 + 欠账计数继续认作我们的），
> 副作用是会把玩家自己敲的 `/trigger ViewStats` 也吞掉，已回退。

### 1.20.2：两端端盖按纹素原尺寸画（圆头）

原版那条条在 GUI 里是 **182 px 宽、1 纹素 = 1 像素**，端盖才看得见：实测
`*_progress.png` 的 0～3 列 / 178～181 列与中间平直段不同 —— 第 0、181 列把**上下两个角的
像素透明度挖成 0**，第 1、180 列整列压暗，2、3 / 178、179 列上下两行略暗。这几列就是「圆头」。

本 Mod 的条只有 50～150 个名牌像素宽，1.20.1 及以前把整张 182 纹素横向压到几十像素，
端盖连带圆角一起被压成 1 px 以下 —— 看起来就是**纯长方形**，与顶部原版 Boss 条的观感对不上。

所以 1.20.2 把纹理切成「左端盖 / 中段 / 右端盖」三个相邻四边形（`BossBarTexture.slices`）：

| 段 | 宽度 | UV | 说明 |
| --- | --- | --- | --- |
| 左端盖 | 固定 `CAP_TEXELS = 4` 纹素 = 4 个布局像素 | 0 → 4 | 只在这段 u 从纹理最左开始时画 |
| 中段 | 剩余长度（拉伸） | 4 → 178 | 中间全是同一列颜色，拉伸看不出来 |
| 右端盖 | 同样 4 纹素 | 178 → 182 | 只在 u 到达纹理最右时画（进度满格时） |

- 端盖 1 纹素 : 1 布局像素，与条高（5 纹素 = 5 布局像素）同比例，所以**不会再被压扁**；
- 进度没满时右边界就应该是**直切**的（原版 `blitSprite` 也是直切），只有满格才露出右端盖；
- 竖向 UV 同时改回 0～1（以前往里收了半个纹素，某些距离下最上/最下一行深色描边会被吃掉）；
- 三个四边形共用完全相同的边界点，不会出缝（1.20.1 修掉的接缝不会再回来）。

A/B 对照图：`versions/v1.20.2/bar-caps.png`（旧=方头 / 新=圆头 / 40% 直切）。

> 早期版本（1.13.x）曾手工拼图集 UV（`getX()/getY()` + 自算图集尺寸），推导偏差会采样到
> 图集别处，表现就是「血条不再是原版纹理」；现在直接指向原版 PNG 文件，资源包替换同样生效。

## 自身属性面板（1.20.3，纯客户端）

上游 Cake Tower HUD Plus 的「属性面板」其实**不需要服务端组件**，做法是：

1. 客户端定时发地图自带的 `/trigger ViewStats`（地图自己 `enable` 过，任何玩家可用，不要 OP）；
2. 地图 `cake_team_tower:misc/view_stats.mcfunction` 用一批 `tellraw @s` 把属性**以 chat 形式**回给本人
   （血量、四色心、碎/粉心、🗡力量、🗡攻速、🛡防御、元素护甲、计时…）；
3. 客户端在 `ClientReceiveMessageEvents.ALLOW_GAME` 里截住这些行 —— **吞掉、不进聊天栏**，
   攒起来按列画成面板；同一趟里按「颜色 + 心形字形」把心数也解析出来。

本 Mod 1.20.3 照这个方式实现了 `SelfStats` + `SelfStatsPanel`：

| 项 | 行为 |
| --- | --- |
| 触发 | `ClientTickEvents` 到点发 `/trigger ViewStats`；`selfStatsSeconds=0` 关闭自动刷新 |
| 采集 | 触发后 3 s 收尾（等不到计时行才用它），单次上限 8 s；只收「带 `Misc_View_Stats_*` 键 / 数字 + 图形（🗡🏹🛡❤…）/ 草方块 `□`」的行（1.20.23 起改用这条窄判据，不再「数字开头就算」） |
| 防刷屏 | 收下的行**不显示**在聊天栏（和上游一样）；1.20.39 起「进存档 / 进服后 3 s 内」既不自动问、也不显示任何 ViewStats 输出（那批只可能是我们自己问出来的迟到回答） |
| 解析 | `heartKindOf(字形, 颜色)`：❤+红/黄/黑/蓝 → 红/魂/黑/蓝；私有区字形 + 暗红/亮紫 → 碎/粉；`amountBefore` 取字形前紧邻的数字 |
| 面板 | 列优先排版，列数 1~3，位置 `selfStatsX/Y`（**相对位置**：像素量在 `layoutGuiW × layoutGuiH` 那套 GUI 下，1.20.40 起按当前尺寸换算；**1.20.41 起默认 x=4、y = 屏幕高 ÷ 3**，即左侧偏上），界面上用「移动面板」拖动，支持字号/透明度 |
| 门控 | 地图回「Game not started」时整块不画（1.20.36 的「选过职业」门控已在 1.20.37 回退） |

## 已知限制

- 只在 **26.3** 上验证；1.21.4 需另开分支。
- **纯客户端**下精确血量只覆盖 Boss 栏指向的那一只，其余是百分比；装了服务端组件后每只怪都有绝对值。
- 队友的黑/蓝/碎心客户端拿不到（`spectator_bossbar` 只有 `AllHearts/MaxHP`），那一行保持 `当前/最大`；
  同一套服务端通道扩一列即可补上，尚未做。
- 队友头顶条优先用「队伍血量」这条 Boss 栏；1.20.4 起在队伍条没有该条目时，用
  `below_name = HealthPercent`（红心 ÷ MaxHP）画百分比回退 —— 这条回退**还没在真局里和真人队友一起验证过**。
- 属性面板的过滤粒度受「客户端能看到的颜色」限制：负值统一是灰色，分不出具体属性
  （灰 `🗡` 可能是职业属性/力量/攻速），落到组内默认项；私有区字形已按码位区分（U+E001/E003/E004/E010/E011/E026/E027）。
- 「调整位置」（原「移动面板」）的拖拽用的是原版滑块同款增量位移；自动化环境只能验证「面板会动、坐标会更新」，
  拖到具体位置的精度没法在无头环境里证明。
- 1.20.40 的「位置相对化」只在自检里验过换算数学与状态流转（`scalePos` / `rebase` / 四套面板 / 盾牌）；
  真机上「拖好位置 → 改窗口大小 / 改 GUI 缩放 → 是否仍对得上」**没有实机验证**。
